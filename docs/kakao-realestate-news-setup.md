# 아침 부동산 뉴스 카카오톡 알림 설정 가이드

매일 아침 부동산 관련 뉴스를 자동으로 모아 카카오톡 "나에게 보내기"로 전송하는 GitHub Actions 자동화입니다.

- 워크플로: [`.github/workflows/morning-realestate-kakao.yml`](../.github/workflows/morning-realestate-kakao.yml)
- 스크립트: [`scripts/kakao-realestate-news.js`](../scripts/kakao-realestate-news.js)
- 이 저장소의 학습 게임 콘텐츠와는 무관한 개인용 자동화이며, 독립적으로 동작합니다.

카카오톡으로 메시지를 보내려면 카카오 계정 로그인 동의가 필요해서, **아래 1단계는 반드시 본인이 브라우저에서 직접 진행**해야 합니다. 이 부분만 완료하면 나머지는 자동으로 매일 실행됩니다.

## 1. 카카오 개발자 앱 생성 및 토큰 발급 (최초 1회, 직접 진행)

1. [카카오 개발자 사이트](https://developers.kakao.com)에 접속해 카카오 계정으로 로그인합니다.
2. **내 애플리케이션 → 애플리케이션 추가하기**로 앱을 만듭니다. (앱 이름 예: `부동산 뉴스 알림`)
3. 생성된 앱 → **제품 설정 → 카카오 로그인**에서 활성화를 `ON`으로 변경합니다.
4. 같은 화면의 **Redirect URI**에 아무 값이나 하나 등록합니다. 실제로 그 주소에 서버가 떠 있을 필요는 없고, 다음 단계에서 인가 코드를 복사하는 용도로만 씁니다.
   - 예: `https://localhost:3000`
5. **카카오 로그인 → 동의항목**에서 `카카오톡 메시지 전송` 항목을 확인 상태(필수 동의 또는 선택 동의)로 설정합니다.
   - "나에게 보내기" 용도는 별도 비즈니스 심사 없이 앱 관리자 본인 계정으로 바로 사용할 수 있습니다. (다른 사람에게 보내거나 정식 서비스로 배포하려면 카카오의 별도 심사가 필요하지만, 이 자동화는 본인에게만 보내므로 해당 없습니다.)
6. **앱 설정 → 앱 키**에서 `REST API 키` 값을 복사해 둡니다. → 이후 `KAKAO_REST_API_KEY`로 사용합니다.
7. **카카오 로그인 → 보안**에서 `Client Secret`을 발급/활성화했다면 그 값도 복사해 둡니다. → `KAKAO_CLIENT_SECRET` (활성화하지 않았다면 이 값은 필요 없습니다.)
8. 아래 주소의 `{REST_API_KEY}`와 `{REDIRECT_URI}`를 본인 값으로 바꾼 뒤, 브라우저 주소창에 붙여넣어 이동합니다.

   ```
   https://kauth.kakao.com/oauth/authorize?client_id={REST_API_KEY}&redirect_uri={REDIRECT_URI}&response_type=code&scope=talk_message
   ```

9. 카카오 로그인 후 동의 화면에서 동의하면 등록해둔 Redirect URI로 이동합니다. "사이트에 연결할 수 없음" 같은 오류 페이지가 떠도 정상입니다 — 주소창에 남아있는 `?code=` 뒤의 문자열을 복사합니다.
10. 터미널(맥/리눅스 터미널, 윈도우는 WSL이나 Git Bash)에서 아래 명령을 본인 값으로 바꿔 실행합니다. (`client_secret`을 발급하지 않았다면 해당 줄은 빼고 실행)

    ```bash
    curl -s -X POST https://kauth.kakao.com/oauth/token \
      -H "Content-Type: application/x-www-form-urlencoded" \
      -d "grant_type=authorization_code" \
      -d "client_id={REST_API_KEY}" \
      -d "redirect_uri={REDIRECT_URI}" \
      -d "code={복사한 인가 코드}" \
      -d "client_secret={CLIENT_SECRET}"
    ```

11. 응답 JSON에서 `refresh_token` 값을 복사해 둡니다. (`access_token`은 몇 시간 뒤 만료되므로 따로 저장할 필요가 없습니다 — 자동화가 매번 `refresh_token`으로 새 `access_token`을 발급받습니다.)

## 2. GitHub 저장소에 Secrets 등록

저장소 **Settings → Secrets and variables → Actions → New repository secret**에서 아래를 등록합니다.

| Secret 이름 | 값 | 필수 여부 |
| --- | --- | --- |
| `KAKAO_REST_API_KEY` | 1-6단계에서 복사한 REST API 키 | 필수 |
| `KAKAO_REFRESH_TOKEN` | 1-11단계에서 복사한 refresh_token | 필수 |
| `KAKAO_CLIENT_SECRET` | 1-7단계 Client Secret (발급했다면) | 발급한 경우만 |
| `GH_PAT` | 아래 "3. 토큰 자동 갱신" 참고 | 선택 |
| `DATA_GO_KR_SERVICE_KEY` | 아래 "7. 검단신도시 아파트 실거래가 연동" 참고 | 선택 (없으면 실거래가 섹션만 건너뜀) |

## 3. 토큰 자동 갱신 (선택, 권장)

카카오 `refresh_token`은 정책상 유효기간(기본 약 60일)이 얼마 남지 않으면 갱신 시 새 값으로 재발급됩니다. 워크플로는 새 `refresh_token`을 받으면 자동으로 저장소 Secret을 덮어쓰려고 시도하는데, 여기에는 저장소 Secret을 쓸 수 있는 권한이 필요합니다 (기본 `GITHUB_TOKEN`에는 이 권한이 없습니다).

- **자동 갱신을 원하면**: GitHub에서 `repo` 권한(또는 이 저장소에 대한 Secrets 쓰기 권한을 포함한 fine-grained 권한)을 가진 [Personal Access Token](https://github.com/settings/tokens)을 발급해 `GH_PAT`라는 이름의 Secret으로 등록하세요.
- **등록하지 않으면**: 자동 갱신은 건너뛰고 Actions 로그에 경고만 남습니다. 이 경우 약 2개월에 한 번씩 1단계의 8~11번을 반복해 `KAKAO_REFRESH_TOKEN`을 수동으로 갱신해야 합니다. (갱신을 잊고 있다가 만료되면 알림이 조용히 멈추니, Actions 탭을 가끔 확인해주세요.)

## 4. 동작 확인

Secrets 등록 후 저장소 **Actions → Morning Real Estate News to KakaoTalk → Run workflow** 로 수동 실행해 카카오톡으로 메시지가 오는지 확인하세요. 예약된 스케줄을 기다리지 않고 언제든 이 방법으로 즉시 테스트할 수 있습니다.

## 5. 커스터마이징

`.github/workflows/morning-realestate-kakao.yml` 파일에서 다음을 바로 수정할 수 있습니다.

- **발송 시각**: 매일 **06:07(오전) / 18:07(오후)** KST에 실행됩니다 (`cron: '7 21 * * *'`, `cron: '7 9 * * *'`). GitHub Actions 스케줄은 UTC 기준이라 한국시간(KST, UTC+9)에서 9시간을 뺀 값을 씁니다. 분을 07로 둔 이유는 아래 "참고"에 있습니다.
- **하나의 메시지로 통합**: 부동산 뉴스·검단신도시 뉴스·검단신도시 실거래가를 카카오톡 메시지 한 통에 `[뉴스]`/`[검단]`/`[실거래]` 라벨로 모아 보냅니다(예전에는 뉴스 두 종류를 메시지 두 통으로 나눠 보냈습니다). 메시지는 카카오 text 타입의 안전 길이(약 180자) 안에서 앞쪽 몇 건만 담기고, 전체 목록은 링크로 연결된 페이지에서 볼 수 있습니다.
- **기사 개수**: `ARTICLE_COUNT` 값 (기본 10, 페이지에 보여줄 개수 — 메시지 자체에는 글자수 제한 때문에 이보다 훨씬 적게 들어갑니다)
- **정렬 기준(조회수 대신 보도 매체 수)**: 구글 뉴스 RSS는 조회수를 전혀 제공하지 않습니다(그런 데이터 자체가 없습니다). 그 대신 같은 사건을 보도한 매체 수가 많은 순으로 정렬해서, 여러 매체가 동시에 다룰수록 화제성이 높은 뉴스라는 현실적인 대체 지표로 씁니다. 매체 수가 같으면 최신순으로 다음 기준을 삼습니다.
- **검색어**: `NEWS_QUERY` 값 (구글 뉴스 검색 문법을 그대로 사용합니다. 예: `서울 아파트 when:1d`, `청약 OR 분양 when:1d`). 기본값은 "부동산"이라는 단어 없이 지표명만으로 쓰이는 기사도 잡아내려고 매매가격지수·전세가율·거래량·미분양·기준금리·종합부동산세·갭투자·청약경쟁률·재건축 등 시장 지표·정책·거래 관련 키워드를 폭넓게 OR로 묶어둔 것입니다(`.github/workflows/morning-realestate-kakao.yml` 참고).
- **인천 검단신도시 청약·거래 소식**: 검단신도시 뉴스는 두 검색을 합쳐서 만듭니다.
  - **① 직접 언급** — `GEOMDAN_QUERY`: "검단신도시"/"인천 검단"/"서구 검단"과 반드시 함께 언급된 기사만, 교통(검단선·GTX-D·5호선 연장 등)·분양청약(청약경쟁률·미분양·입주물량 등)·시세거래(실거래가·갭투자 등)·생활 인프라(인구증가·학군 등)·정책금융(대출한도·규제지역 해제 등) 분야의 구체적인 키워드로 찾습니다. `GEOMDAN_KEYWORD`(기본 `검단`)로 제목에 이 단어가 없는 무관한 기사를 한 번 더 걸러냅니다(본문까지는 확인하지 못하고 제목만 봅니다 — 이 스크립트는 기사 본문을 읽지 않습니다).
  - **② 인접 지역 호재** — `GEOMDAN_NEARBY_QUERY`: "검단" 언급이 없어도, 생활권·교통망을 공유해 검단신도시에 영향을 줄 만한 인접 지역(계양신도시·김포 콤팩트시티·청라국제도시·대장신도시·마곡신도시 등 3기 신도시·인접 택지지구) 개발 이슈는 별도로 찾습니다. ①과 합쳐 유사 헤드라인은 하나로 묶고, ①에는 안 걸리고 ②에서만 걸린 기사에는 페이지·카카오톡 메시지 모두에 "🔗 인접 지역 호재" 딱지만 붙입니다 — 기사 본문을 요약하는 기능은 없어서, 실제로 검단신도시에 어떤 영향을 주는지는 딱지를 보고 직접 판단해야 합니다.
  - 두 검색 결과를 합쳐 `GEOMDAN_ARTICLE_COUNT`(기본 10)건까지 페이지에 보여줍니다. 정확한 검색어 값은 `.github/workflows/morning-realestate-kakao.yml` 참고.
- **검단신도시 아파트 실거래가**: `LAWD_CD`(기본 `28290`, 검단구), `GEOMDAN_DONGS`(기본 `당하동,마전동,불로동,원당동` — 검단구 관할 중 실제 신도시로 개발된 법정동만), `GEOMDAN_TRANSACTION_DAYS`(기본 30, 오늘 포함 최근 며칠 이내 계약 건만), `GEOMDAN_TRANSACTION_COUNT`(기본 50, 평당가 높은 순)로 조정합니다. 공급면적 추정치 기준 **평당가**(1평=3.3058㎡ 환산)도 함께 보여줍니다. 자세한 내용은 아래 "7. 검단신도시 아파트 실거래가 연동" 참고.
- **개인 블로그 글은 포함되지 않습니다**: 구글 뉴스는 정식 언론사 기사만 색인하고 네이버 블로그 같은 개인 블로그는 애초에 포함하지 않습니다. 부동산 블로그 글까지 보려면 네이버 블로그 검색 API 같은 별도 데이터 소스와 그에 맞는 API 키가 새로 필요합니다 — 아직 연동돼 있지 않습니다.

## 참고

- 뉴스는 별도 API 키가 필요 없는 Google 뉴스 RSS 검색을 사용합니다.
- 이 저장소는 60일 이상 아무 커밋도 없으면 GitHub가 예약 워크플로를 자동으로 비활성화합니다. 저장소를 계속 사용 중이라면 문제되지 않지만, 알림이 갑자기 멈추면 Actions 탭에서 워크플로가 비활성화되지 않았는지 먼저 확인하세요.
- **예약 실행 시각은 정확히 보장되지 않습니다**: GitHub Actions의 `schedule` 트리거는 공식적으로 "최선 노력"이며, 특히 매시 정각(0분)에 요청이 몰려 지연이 심해집니다. 이 저장소는 분을 07로 둬서 정각 혼잡을 피하지만, 그래도 GitHub 서버 상황에 따라 몇 분~몇 시간 늦어질 수 있습니다. 정확한 시각이 꼭 필요하면 GitHub Actions의 `schedule` 대신, 외부 스케줄러가 `workflow_dispatch`를 API로 직접 호출하는 방식으로 바꿔야 합니다(이 저장소에는 아직 적용돼 있지 않습니다).

## 6. 오픈채팅방(예: 재부키)에도 매일 아침 뉴스 올리기 (선택)

**카카오는 봇이나 외부 프로그램이 오픈채팅방에 대신 글을 올려주는 공식 API를 제공하지 않습니다.** (본인에게 보내는 "나에게 보내기"와는 완전히 별개 기능이며, 오픈채팅방에 자동으로 글을 쓰게 해주는 개발자 API 자체가 없습니다.) 그래서 아래와 같이 우회합니다.

- 이 자동화는 실행될 때마다 부동산 뉴스·검단신도시 뉴스·검단신도시 실거래가를 모두 담은 같은 내용을 `docs/index.html`과 `docs/geomdan.html` 두 파일에 동일하게 갱신해서 저장소에 커밋합니다(예전에 geomdan.html을 따로 북마크/공지해둔 경우에도 링크가 깨지지 않도록 둘 다 같은 내용을 담습니다).
- 그 페이지를 **GitHub Pages**로 공개하면 주소가 하나로 고정됩니다 (예: `https://lifelongdt-beep.github.io/game/`). 페이지 내용은 매번 바뀌지만 링크는 항상 같습니다.
- 그 고정 링크를, 오픈채팅방을 직접 운영 중이신 경우 **카카오톡 자체 기능인 "방장봇" 공지/알림 메시지**에 등록해두면, 정해둔 시각(예: 매일 06:07~07:00 사이)에 방에 자동으로 공지가 올라오고, 멤버들이 눌러보면 그날 최신 뉴스를 볼 수 있습니다.
- 방장봇은 카카오톡 앱 자체 기능이라 로그인된 본인 계정에서 직접 설정해야 합니다 — 이 부분은 대신해드릴 수 없어요.

### 6-1. GitHub Pages 활성화 (최초 1회)

1. 저장소 **Settings → Pages**로 이동합니다.
2. **Source**를 `Deploy from a branch`로, **Branch**를 `main` / `/docs`로 설정하고 저장합니다.
3. 잠시 후 `https://{GitHub 사용자명}.github.io/game/` 주소로 접속되는지 확인합니다. (아직 워크플로를 한 번도 안 돌렸다면 4단계를 먼저 진행해 `docs/index.html`/`docs/geomdan.html`을 만들어야 페이지가 뜹니다.)
4. 위 "4. 동작 확인"에서처럼 Actions 탭에서 워크플로를 한 번 수동 실행(`Run workflow`)해 두 페이지가 자동 커밋되는지 확인합니다.
5. 이 저장소는 공개(public) 저장소라 이 페이지도 링크를 아는 누구나 볼 수 있습니다. 부동산 뉴스 제목/링크만 담기니 문제는 없지만 참고해주세요.

### 6-2. 카카오톡 방장봇에 공지 등록 (최초 1회, 직접 진행)

1. 카카오톡 앱에서 재부키 오픈채팅방으로 이동합니다.
2. 채팅방 우측 상단 메뉴(≡) → 채팅방 설정에서 **방장봇** 관리 화면으로 들어갑니다. (카카오톡 버전에 따라 메뉴 위치/이름이 조금 다를 수 있습니다.)
3. 공지/알림 메시지를 새로 등록하고, 원하는 발송 시각(예: 매일 오전 6시 30분)과 메시지 내용을 입력합니다. 메시지 본문에 6-1에서 확인한 Pages 링크를 넣어주세요.
   - 예시: `🏠 오늘의 부동산 뉴스가 올라왔어요 → https://lifelongdt-beep.github.io/game/`
4. 저장하면 이후로는 카카오톡이 매일 정해진 시각에 이 방에 알아서 공지를 올립니다. 클릭하면 그날 자동 갱신된 뉴스 페이지가 열립니다.

### 시간 맞추기

방장봇 공지 시각은 페이지가 이미 그날 내용으로 갱신된 뒤여야 합니다. 워크플로 기본 실행 시각(오전 06:07 KST)보다 방장봇 공지 시각을 여유 있게 뒤로 잡아주세요 (예: 06:20 이후). (워크플로 실행 시각을 바꾸는 방법은 위 "5. 커스터마이징" 참고.)

## 7. 검단신도시 아파트 실거래가 연동 (선택)

`docs/geomdan.html`의 "🏘️ 아파트 실거래가" 섹션은 뉴스 기사가 아니라 국토교통부가 공공데이터포털을 통해 공개하는 **공식 실거래 신고 자료**(실제 계약 내역)를 보여줍니다. 이 시크릿을 등록하지 않아도 이 섹션만 조용히 비워질 뿐, 나머지(뉴스 수집, 카카오톡 발송)는 그대로 동작합니다.

### 7-1. 공공데이터포털 API 키 발급 (최초 1회, 직접 진행)

1. [공공데이터포털](https://www.data.go.kr)에서 회원가입 후 로그인합니다.
2. [국토교통부_아파트 매매 실거래가 상세 자료](https://www.data.go.kr/data/15126468/openapi.do) 페이지에서 **활용신청** 버튼을 누르고 활용 목적을 간단히 입력해 신청합니다. (이 데이터셋은 대부분 자동승인이라 몇 분 안에 승인됩니다.)
3. 승인 후 **마이페이지 → 데이터활용 → Open API → 활용신청 현황**에서 해당 항목을 열어 **일반 인증키(Encoding)** 값을 복사합니다.
   - ⚠️ 반드시 **Encoding** 값을 복사하세요 (Decoding 값이 아닙니다). URL에 바로 쓸 수 있도록 미리 인코딩되어 있는 값입니다.

### 7-2. GitHub Secret 등록

저장소 **Settings → Secrets and variables → Actions → New repository secret**에서 아래를 등록합니다.

| Secret 이름 | 값 |
| --- | --- |
| `DATA_GO_KR_SERVICE_KEY` | 7-1에서 복사한 일반 인증키(Encoding) 값 |

등록 후 위 "4. 동작 확인"과 동일하게 워크플로를 수동 실행(`Run workflow`)해서 `docs/geomdan.html`에 실거래가 목록이 뜨는지 확인하세요.

### 7-3. 지역 범위 조정

기본값은 **검단구**(`LAWD_CD=28290`) 전체를 조회한 뒤, 그중 실제 신도시로 개발된 법정동(`GEOMDAN_DONGS` 기본값: `당하동,마전동,불로동,원당동`)만 걸러서 보여줍니다. 검단구 관할에는 그 외에도 오류동·왕길동·금곡동·대곡동·백석동·시천동이 있지만, "검단신도시"로 개발된 지역은 아니라서 기본값에서 제외했습니다. 다른 지역/범위로 바꾸려면 `.github/workflows/morning-realestate-kakao.yml`의 `LAWD_CD`(5자리 법정동 시군구 코드)와 `GEOMDAN_DONGS`(쉼표로 구분한 법정동명)를 수정하세요. 그중에서도 오늘 포함 최근 `GEOMDAN_TRANSACTION_DAYS`일(기본 30일) 이내에 계약된 건만 남기고, 평당가(공급면적 추정치 기준)가 높은 순으로 정렬해 `GEOMDAN_TRANSACTION_COUNT`(기본 50)건까지 보여줍니다.

### 7-4. 평당가는 어떻게 계산하나요

국토교통부 실거래가 API가 제공하는 면적은 **전용면적**(방·거실·주방 등 실제 거주 공간)뿐인데, 한국 부동산 시장에서 관용적으로 쓰는 "평당가"·"OO평형" 표기는 **공급면적**(전용면적 + 계단실·복도 등 주거공용면적) 기준입니다. 전용면적을 그대로 평으로 환산해 평당가를 매기면 실제 시세 기사·부동산 사이트에서 보는 값보다 25~35% 높게 나옵니다.

이 API에는 공급면적 자체가 없고, 단지·주택형별 공급면적은 별도의 공공데이터포털 데이터셋으로도 안정적으로 조회할 수 없어서(분양 공고 PDF나 부동산 정보 사이트에 개별적으로만 존재), 검단신도시 여러 단지(검단신도시푸르지오더베뉴, 유승한내들에듀파크, 검단신도시예미지트리플에듀 등)의 실제 분양·관리비 고지 면적을 찾아 확인한 **전용률**(전용면적 ÷ 공급면적)을 바탕으로 공급면적을 역산합니다. 확인해보니 전용률이 전용면적 구간별로 74~79% 안팎에 모여 있어(예: 전용 75.84㎡→공급 99.07㎡, 전용 84.24㎡→공급 109.43㎡, 전용 102.85㎡→공급 130.65㎡), 아래처럼 구간별 평균값을 `scripts/kakao-realestate-news.js`의 `EXCLUSIVE_RATIO_BANDS`에 넣어뒀습니다.

| 전용면적 | 적용 전용률 |
| --- | --- |
| 60㎡ 미만 | 75.0% |
| 60~80㎡ 미만 | 76.5% |
| 80~95㎡ 미만 | 76.8% |
| 95~120㎡ 미만 | 78.5% |
| 120㎡ 이상 | 80.0% |

이렇게 역산한 공급면적은 단지마다 등기부에 등록된 정확한 값과는 소수점 단위로 다를 수 있는 **추정치**입니다. 페이지 하단의 "평당가는 공급면적 추정치 기준" 안내가 이 뜻입니다. 더 정확한 값이 필요하면 새로 조회된 단지의 실제 공급면적을 찾아 `EXCLUSIVE_RATIO_BANDS`를 단지별 값으로 세분화하세요.

### 참고

- 실거래 신고는 계약 후 최대 30일까지 지연될 수 있어 이번 달 초에는 자료가 거의 없을 수 있습니다. 그래서 이번 달·지난달·지지난달 자료를 함께 조회한 뒤(`GEOMDAN_TRANSACTION_DAYS` 기본값인 30일을 달 경계에 걸린 날짜까지 안전하게 커버하기 위해 석 달치를 봅니다), 그중 평당가가 높은 순으로 보여줍니다.
- API 키가 아직 심사 중이거나 잘못 등록된 경우 Actions 로그에 오류 메시지가 남고, 그 실행에서는 실거래가 섹션만 빈 채로 나머지는 정상 진행됩니다.
- **`LAWD_CD=28290`(검단구)인 이유**: 2026년 7월 1일 인천시 행정구역 개편(법률 제20161호)으로 검단신도시 일대가 기존 서구에서 분리되어 별도 자치구 "검단구"가 됐습니다. 예전 서구 코드(`28260`)는 더 이상 이 지역 실거래를 포함하지 않습니다. 나중에 이 지역이 또 개편되어 실거래가가 갑자기 0건으로 보인다면, 가장 먼저 지역코드가 바뀌지 않았는지 의심해보세요.
