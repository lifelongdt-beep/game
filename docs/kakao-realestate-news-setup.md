# 아침 부동산 뉴스 카카오톡 알림 설정 가이드

매일 아침 부동산 관련 뉴스를 자동으로 모아 카카오톡 "나에게 보내기"로 전송하는 GitHub Actions 자동화입니다.

- 워크플로: [`.github/workflows/morning-realestate-kakao.yml`](../.github/workflows/morning-realestate-kakao.yml)
- 스크립트: [`scripts/kakao-realestate-news.js`](../scripts/kakao-realestate-news.js)
- 이 저장소의 학습 게임 콘텐츠와는 무관한 개인용 자동화이며, 독립적으로 동작합니다.

카카오톡으로 메시지를 보내려면 카카오 계정 로그인 동의가 필요해서, **아래 1단계는 반드시 본인이 브라우저에서 직접 진행**해야 합니다. 이 부분만 완료하면 나머지는 자동으로 매일 실행됩니다.

## 1. 카카오 개발자 앱 생성 및 토큰 발급 (최초 1회, 직접 진행)

1. [카카오 개발자 사이트](https://developers.kakao.com)에 접속해 카카오 계정으로 로그인합니다.
2. **내 애플리케이션 → 애플리케이션 추가하기**로 앱을 만듭니다. (앱 이름 예: `부동산 뉴스 알림`)
3. 생성된 앱 → **제품 설정 → 카카오 로그인**에서 활성화를 `ON`으로 변경합니다.
4. 같은 화면의 **Redirect URI**에 아무 값이나 하나 등록합니다. 실제로 그 주소에 서버가 떠 있을 필요는 없고, 다음 단계에서 인가 코드를 복사하는 용도로만 씁니다.
   - 예: `https://localhost:3000`
5. **카카오 로그인 → 동의항목**에서 `카카오톡 메시지 전송` 항목을 확인 상태(필수 동의 또는 선택 동의)로 설정합니다.
   - "나에게 보내기" 용도는 별도 비즈니스 심사 없이 앱 관리자 본인 계정으로 바로 사용할 수 있습니다. (다른 사람에게 보내거나 정식 서비스로 배포하려면 카카오의 별도 심사가 필요하지만, 이 자동화는 본인에게만 보내므로 해당 없습니다.)
6. **앱 설정 → 앱 키**에서 `REST API 키` 값을 복사해 둡니다. → 이후 `KAKAO_REST_API_KEY`로 사용합니다.
7. **카카오 로그인 → 보안**에서 `Client Secret`을 발급/활성화했다면 그 값도 복사해 둡니다. → `KAKAO_CLIENT_SECRET` (활성화하지 않았다면 이 값은 필요 없습니다.)
8. 아래 주소의 `{REST_API_KEY}`와 `{REDIRECT_URI}`를 본인 값으로 바꾼 뒤, 브라우저 주소창에 붙여넣어 이동합니다.

   ```
   https://kauth.kakao.com/oauth/authorize?client_id={REST_API_KEY}&redirect_uri={REDIRECT_URI}&response_type=code&scope=talk_message
   ```

9. 카카오 로그인 후 동의 화면에서 동의하면 등록해둔 Redirect URI로 이동합니다. "사이트에 연결할 수 없음" 같은 오류 페이지가 떠도 정상입니다 — 주소창에 남아있는 `?code=` 뒤의 문자열을 복사합니다.
10. 터미널(맥/리눅스 터미널, 윈도우는 WSL이나 Git Bash)에서 아래 명령을 본인 값으로 바꿔 실행합니다. (`client_secret`을 발급하지 않았다면 해당 줄은 빼고 실행)

    ```bash
    curl -s -X POST https://kauth.kakao.com/oauth/token \
      -H "Content-Type: application/x-www-form-urlencoded" \
      -d "grant_type=authorization_code" \
      -d "client_id={REST_API_KEY}" \
      -d "redirect_uri={REDIRECT_URI}" \
      -d "code={복사한 인가 코드}" \
      -d "client_secret={CLIENT_SECRET}"
    ```

11. 응답 JSON에서 `refresh_token` 값을 복사해 둡니다. (`access_token`은 몇 시간 뒤 만료되므로 따로 저장할 필요가 없습니다 — 자동화가 매번 `refresh_token`으로 새 `access_token`을 발급받습니다.)

## 2. GitHub 저장소에 Secrets 등록

저장소 **Settings → Secrets and variables → Actions → New repository secret**에서 아래를 등록합니다.

| Secret 이름 | 값 | 필수 여부 |
| --- | --- | --- |
| `KAKAO_REST_API_KEY` | 1-6단계에서 복사한 REST API 키 | 필수 |
| `KAKAO_REFRESH_TOKEN` | 1-11단계에서 복사한 refresh_token | 필수 |
| `KAKAO_CLIENT_SECRET` | 1-7단계 Client Secret (발급했다면) | 발급한 경우만 |
| `GH_PAT` | 아래 "3. 토큰 자동 갱신" 참고 | 선택 |
| `DATA_GO_KR_SERVICE_KEY` | 아래 "7. 검단신도시 아파트 실거래가 연동" 참고 | 선택 (없으면 실거래가 섹션만 건너뜀) |

## 3. 토큰 자동 갱신 (선택, 권장)

카카오 `refresh_token`은 정책상 유효기간(기본 약 60일)이 얼마 남지 않으면 갱신 시 새 값으로 재발급됩니다. 워크플로는 새 `refresh_token`을 받으면 자동으로 저장소 Secret을 덮어쓰려고 시도하는데, 여기에는 저장소 Secret을 쓸 수 있는 권한이 필요합니다 (기본 `GITHUB_TOKEN`에는 이 권한이 없습니다).

- **자동 갱신을 원하면**: GitHub에서 `repo` 권한(또는 이 저장소에 대한 Secrets 쓰기 권한을 포함한 fine-grained 권한)을 가진 [Personal Access Token](https://github.com/settings/tokens)을 발급해 `GH_PAT`라는 이름의 Secret으로 등록하세요.
- **등록하지 않으면**: 자동 갱신은 건너뛰고 Actions 로그에 경고만 남습니다. 이 경우 약 2개월에 한 번씩 1단계의 8~11번을 반복해 `KAKAO_REFRESH_TOKEN`을 수동으로 갱신해야 합니다. (갱신을 잊고 있다가 만료되면 알림이 조용히 멈추니, Actions 탭을 가끔 확인해주세요.)

## 4. 동작 확인

Secrets 등록 후 저장소 **Actions → Morning Real Estate News to KakaoTalk → Run workflow** 로 수동 실행해 카카오톡으로 메시지가 오는지 확인하세요. 예약된 스케줄을 기다리지 않고 언제든 이 방법으로 즉시 테스트할 수 있습니다.

## 5. 커스터마이징

`.github/workflows/morning-realestate-kakao.yml` 파일에서 다음을 바로 수정할 수 있습니다.

- **발송 시각**: 매일 **06:07(오전) / 18:07(오후)** KST에 실행됩니다 (`cron: '7 21 * * *'`, `cron: '7 9 * * *'`). GitHub Actions 스케줄은 UTC 기준이라 한국시간(KST, UTC+9)에서 9시간을 뺀 값을 씁니다. 분을 07로 둔 이유는 아래 "참고"에 있습니다.
- **하나의 메시지로 통합**: 부동산 뉴스·검단신도시 뉴스·검단신도시 실거래가를 카카오톡 메시지 한 통에 `[뉴스]`/`[검단]`/`[실거래]` 라벨로 모아 보냅니다(예전에는 뉴스 두 종류를 메시지 두 통으로 나눠 보냈습니다). 메시지는 카카오 text 타입의 안전 길이(약 180자) 안에서 앞쪽 몇 건만 담기고, 전체 목록은 링크로 연결된 페이지에서 볼 수 있습니다.
- **오픈채팅방 초대 문구**: `OPENCHAT_INVITE_TEXT`(문구)와 `OPENCHAT_URL`(링크)로 만든 오픈채팅방 초대 문구가 `docs/index.html`/`docs/geomdan.html` 페이지의 "🏘️ 검단신도시 아파트 실거래가" 섹션 바로 아래(페이지 맨 마지막)에 클릭 가능한 링크로 표시됩니다. 카카오톡 메시지 자체(첫 화면)에는 넣지 않습니다 — 메시지 안에 "기사 보기" 버튼 링크와 오픈채팅방 링크가 같이 있으면 산만해서, 페이지 쪽에만 두기로 했습니다.
- **기사 개수**: `ARTICLE_COUNT` 값 (기본 20, 페이지에 보여줄 개수 — 메시지 자체에는 글자수 제한 때문에 이보다 훨씬 적게 들어갑니다)
- **정렬 기준(조회수 대신 보도 매체 수)**: 구글 뉴스 RSS는 조회수를 전혀 제공하지 않습니다(그런 데이터 자체가 없습니다). 그 대신 같은 사건을 보도한 매체 수가 많은 순으로 정렬해서, 여러 매체가 동시에 다룰수록 화제성이 높은 뉴스라는 현실적인 대체 지표로 씁니다. 매체 수가 같으면 최신순으로 다음 기준을 삼습니다.
- **검색어**: `NEWS_QUERY` 값 (구글 뉴스 검색 문법을 그대로 사용합니다. 예: `서울 아파트 when:1d`, `청약 OR 분양 when:1d`). 기본값은 "부동산"이라는 단어 없이 지표명만으로 쓰이는 기사도 잡아내려고 매매가격지수·전세가율·거래량·미분양·기준금리·종합부동산세·갭투자·청약경쟁률·재건축 등 시장 지표·정책·거래 관련 키워드를 폭넓게 OR로 묶어둔 것입니다(`.github/workflows/morning-realestate-kakao.yml` 참고).
- **인천 검단신도시 청약·거래 소식**: 검단신도시 뉴스는 두 검색을 합쳐서 만듭니다.
  - **① 직접 언급** — `GEOMDAN_QUERY`: "검단신도시"/"검단"(단독어)/"인천 검단"/"서구 검단"/"검단구"/"중흥S클래스"/"검단호수공원"/"당하동"/"마전동"이 언급된(2026-11-26 보강: 제목에 "검단신도시"가 없는 단지·교통·산단 기사도 잡도록 "검단" 단독어를 넣었고, 하남 검단산은 `-검단산`으로 제외. 오류왕길동 행사성·구로구 오류동 기사가 섞여 동 이름 중 당하동·마전동만 추가) 기사는 분야를 가리지 않고 전부 찾습니다. "검단구"는 2026-07-01 행정구역 개편으로 생긴 명칭이라 지역 키워드에 미리 포함해뒀습니다. `GEOMDAN_KEYWORD`(기본 `검단`)로 제목에 이 단어가 없는 무관한 기사를 한 번 더 걸러냅니다(본문까지는 확인하지 못하고 제목만 봅니다 — 이 스크립트는 기사 본문을 읽지 않습니다). 예전에는 교통·분양청약·시세거래·생활 인프라·정책금융 등 특정 주제 키워드와의 AND 조건으로 좁혔었는데, I-MOD 버스 종료처럼 부동산 시장 이슈가 아닌 교통·행정·생활 소식도 검단신도시 뉴스가 맞다는 피드백에 따라 이 AND 조건은 제거했습니다.
  - **② 인접지역** — `GEOMDAN_NEARBY_QUERY`: "검단" 언급이 없어도, 생활권·교통망을 공유해 검단신도시에 영향을 줄 만한 인접 지역(계양신도시·김포 콤팩트시티·청라국제도시·대장신도시·마곡신도시 등 3기 신도시·인접 택지지구) 개발 이슈는 별도로 찾습니다. ①과 합쳐 유사 헤드라인은 하나로 묶고, ①에는 안 걸리고 ②에서만 걸린 기사에는 페이지·카카오톡 메시지 모두에 "🔗 인접지역" 딱지만 붙입니다 — 기사 본문을 요약하는 기능은 없어서, 실제로 검단신도시에 어떤 영향을 주는지, 호재인지 악재인지는 딱지를 보고 직접 판단해야 합니다(예전엔 "인접 지역 호재"라고 썼는데, 7호선 청라 연장 공사중단처럼 악재성 기사에도 이 딱지가 붙는 걸 보고 "호재" 표현을 뺐습니다). 카드뉴스 슬라이드에 이런 인접지역 기사를 쓸 때는 특히 주의할 점이 있습니다 — 예를 들어 "7호선 청라국제도시 연장"은 **검단신도시와 계획 단계로도 이어지지 않는, 완전히 무관한 별개 노선**입니다("아직 계획 단계"조차 아님 — 그렇게 쓰는 것도 없는 연관성을 지어내는 것이므로 금지). 청라 구간 공사 이슈를 검단 접근성과 연결 짓는 서술은 어떤 형태로도 쓰지 마세요. "재부키 인사이트" 박스는 실제 연관성이 없으면 억지로 검단과 엮지 말고, 그 기사 자체가 주는 일반적인 교훈으로 채우면 됩니다(예: "지하철 7호선 공사 일시 중단 뉴스를 통해 지하철 공사는 여러 가지 이유로 연기될 수 있다는 점을 항상 인지하고 있어야 합니다" — 검단을 언급하지 않고 그 기사가 시사하는 보편적 시사점만 씀). 검단신도시 자체와 실제로 관련된 기사를 다룰 때만 서부권 광역급행철도·GTX-D처럼 진짜 관련 사업을 근거로 인사이트를 쓰세요.
  - 두 검색 결과를 합쳐 `GEOMDAN_ARTICLE_COUNT`(기본 20)건까지 페이지에 보여줍니다. 정확한 검색어 값은 `.github/workflows/morning-realestate-kakao.yml` 참고.
  - **24시간 이내만 표시**: 구글 뉴스의 `when:1d`는 정확히 자정 기준이 아니라 24시간 롤링 윈도우입니다. 검단신도시 뉴스는 발행시각을 한 번 더 확인해서 실제로 발행 후 24시간이 지나지 않은 기사만 남깁니다(발행시각을 읽지 못한 기사도 확인할 수 없으므로 제외). 예전에는 "KST 달력 날짜가 오늘과 같은가"로 확인했는데, 그러면 예를 들어 어제 오후에 나온 기사(아직 24시간 이내)가 다음날 오전 실행분에서는 "어제 날짜"라는 이유만으로 잘려나가는 문제가 있었습니다(검단호수공원역 풍경채 어바니티 2차 청약 기사가 실제로 이렇게 빠진 걸 확인해서 고쳤습니다). 일반 부동산 뉴스(`NEWS_QUERY`)에는 이 필터를 적용하지 않습니다.
- **검단신도시 아파트 실거래가**: `LAWD_CD`(기본 `28290`, 검단구), `GEOMDAN_DONGS`(기본 `당하동,마전동,불로동,원당동` — 검단구 관할 중 실제 신도시로 개발된 법정동만), `GEOMDAN_TRANSACTION_MONTHS`(기본 4, 오늘 포함 최근 몇 개월 이내 계약 건만), `GEOMDAN_TRANSACTION_COUNT`(기본 800, 평당가 높은 순)로 조정합니다. 신도시가 아닌 기존 단지는 `scripts/geomdan-excluded-apartments.txt`에 이름을 적어 빼며(아래 7-3 참고) 공급면적 추정치 기준 **평당가**(1평=3.3058㎡ 환산)도 함께 보여줍니다. data.go.kr가 `GEOMDAN_TRANSACTION_FALLBACK_BUDGET_MS`(기본 30000, 30초) 안에 응답하지 않으면 마지막으로 성공했던 캐시 데이터로 임시 대체합니다. 자세한 내용은 아래 "7. 검단신도시 아파트 실거래가 연동" 참고.
- **개인 블로그 글은 포함되지 않습니다**: 구글 뉴스는 정식 언론사 기사만 색인하고 네이버 블로그 같은 개인 블로그는 애초에 포함하지 않습니다. 부동산 블로그 글까지 보려면 네이버 블로그 검색 API 같은 별도 데이터 소스와 그에 맞는 API 키가 새로 필요합니다 — 아직 연동돼 있지 않습니다.

## 6. 오픈채팅방(예: 재부키)에도 매일 아침 뉴스 올리기 (선택)

**카카오는 봇이나 외부 프로그램이 오픈채팅방에 대신 글을 올려주는 공식 API를 제공하지 않습니다.** (본인에게 보내는 "나에게 보내기"와는 완전히 별개 기능이며, 오픈채팅방에 자동으로 글을 쓰게 해주는 개발자 API 자체가 없습니다.) 그래서 아래와 같이 우회합니다.

- 이 자동화는 실행될 때마다 부동산 뉴스·검단신도시 뉴스·검단신도시 실거래가를 모두 담은 같은 내용을 `docs/index.html`과 `docs/geomdan.html` 두 파일에 동일하게 갱신해서 저장소에 커밋합니다(예전에 geomdan.html을 따로 북마크/공지해둔 경우에도 링크가 깨지지 않도록 둘 다 같은 내용을 담습니다).
- 그 페이지를 **GitHub Pages**로 공개하면 주소가 하나로 고정됩니다 (예: `https://lifelongdt-beep.github.io/game/`). 페이지 내용은 매번 바뀌지만 링크는 항상 같습니다.
- 그 고정 링크를, 오픈채팅방을 직접 운영 중이신 경우 **카카오톡 자체 기능인 "방장봇" 공지/알림 메시지**에 등록해두면, 정해둔 시각(예: 매일 06:07~07:00 사이)에 방에 자동으로 공지가 올라오고, 멤버들이 눌러보면 그날 최신 뉴스를 볼 수 있습니다.
- 방장봇은 카카오톡 앱 자체 기능이라 로그인된 본인 계정에서 직접 설정해야 합니다 — 이 부분은 대신해드릴 수 없어요.

## 7. 검단신도시 아파트 실거래가 연동 (선택)

`docs/geomdan.html`의 "🏘️ 아파트 실거래가" 섹션은 뉴스 기사가 아니라 국토교통부가 공공데이터포털을 통해 공개하는 **공식 실거래 신고 자료**(실제 계약 내역)를 보여줍니다. 이 시크릿을 등록하지 않아도 이 섹션만 조용히 비워질 뿐, 나머지(뉴스 수집, 카카오톡 발송)는 그대로 동작합니다.

### 7-1. 공공데이터포털 API 키 발급 (최초 1회, 직접 진행)

1. [공공데이터포털](https://www.data.go.kr)에서 회원가입 후 로그인합니다.
2. [국토교통부_아파트 매매 실거래가 상세 자료](https://www.data.go.kr/data/15126468/openapi.do) 페이지에서 **활용신청** 버튼을 누르고 활용 목적을 간단히 입력해 신청합니다. (이 데이터셋은 대부분 자동승인이라 몇 분 안에 승인됩니다.)
3. 승인 후 **마이페이지 → 데이터활용 → Open API → 활용신청 현황**에서 해당 항목을 열어 **일반 인증키(Encoding)** 값을 복사합니다.
   - ⚠️ 반드시 **Encoding** 값을 복사하세요 (Decoding 값이 아닙니다). URL에 바로 쓸 수 있도록 미리 인코딩되어 있는 값입니다.

### 7-2. GitHub Secret 등록

저장소 **Settings → Secrets and variables → Actions → New repository secret**에서 아래를 등록합니다.

| Secret 이름 | 값 |
| --- | --- |
| `DATA_GO_KR_SERVICE_KEY` | 7-1에서 복사한 일반 인증키(Encoding) 값 |

등록 후 위 "4. 동작 확인"과 동일하게 워크플로를 수동 실행(`Run workflow`)해서 `docs/geomdan.html`에 실거래가 목록이 뜨는지 확인하세요.

### 7-3. 지역 범위 조정

기본값은 **검단구**(`LAWD_CD=28290`) 전체를 조회한 뒤, 그중 실제 신도시로 개발된 법정동(`GEOMDAN_DONGS` 기본값: `당하동,마전동,불로동,원당동`)만 걸러서 보여줍니다. 검단구 관할에는 그 외에도 오류동·왕길동·금곡동·대곡동·백석동·시천동이 있지만, "검단신도시"로 개발된 지역은 아니라서 기본값에서 제외했습니다. 다른 지역/범위로 바꾸려면 `.github/workflows/morning-realestate-kakao.yml`의 `LAWD_CD`(5자리 법정동 시군구 코드)와 `GEOMDAN_DONGS`(쉼표로 구분한 법정동명)를 수정하세요. 그중에서도 오늘 포함 최근 `GEOMDAN_TRANSACTION_MONTHS`개월(기본 4개월, 10/3이면 6/4부터) 이내에 계약된 건만 남기고, 평당가(공급면적 추정치 기준)가 높은 순으로 정렬해 `GEOMDAN_TRANSACTION_COUNT`(기본 800)건까지 보여줍니다.

**신도시가 아닌 기존 단지 빼기**: 같은 법정동 안에도 검단신도시로 개발되기 전부터 있던 옛 아파트(예: 마전동 검단아이파크, 당하동 당하푸르지오)가 섞여 나오므로, 이런 단지는 `scripts/geomdan-excluded-apartments.txt`에 한 줄에 하나씩 적으면 실거래가 목록과 평당 순위에서 빠집니다(실거래가 API의 단지명 그대로 적되, 공백·괄호 안 덧붙임·대소문자는 무시하고 비교합니다). 2026-10-03에 평당가 1,500만 원 이하로 나오던 단지 34곳을 처음 넣고, 같은 날 조회 기간을 4개월로 늘리자 새로 보인 같은 종류의 단지 29곳을 더해 63곳이 들어 있습니다. 카드뉴스를 만들 때 `build-card.js`가 평당 1,500만 원 이하 단지가 순위에 보이면 경고를 출력하니, 새로 나온 기존 단지는 그때 이 파일에 추가하세요.

**목록 상한과 단지 순위**: 목록은 `GEOMDAN_TRANSACTION_COUNT`건(기본 800)에서 잘립니다. 4개월치 신도시 거래는 2026-10-03 기준 543건이라 지금은 전부 들어가지만(늦게 신고되는 거래가 더해지면 조금씩 늘어납니다), 상한을 낮추면 평당가 높은 거래만 남습니다(200건이면 20개 안팎 단지뿐). 그래서 카드뉴스의 단지 순위는 목록이 아니라 잘리기 전 전체 거래에서 뽑은 "단지별 최고 거래"로 만듭니다. 스크립트가 이 데이터를 `docs/index.html` 안의 화면에 보이지 않는 JSON(`<script type="application/json" id="geomdan-complex-ranking">`)과 `docs/geomdan-transactions-cache.json`의 `ranking` 항목으로 함께 저장하고, `build-card.js`가 읽습니다(없으면 예전처럼 하단 목록으로 순위를 계산하고, 목록이 상한에 걸려 있으면 경고합니다).

### 7-4. 평당가는 어떻게 계산하나요

국토교통부 실거래가 API가 제공하는 면적은 **전용면적**(방·거실·주방 등 실제 거주 공간)뿐인데, 한국 부동산 시장에서 관용적으로 쓰는 "평당가"·"OO평형" 표기는 **공급면적**(전용면적 + 계단실·복도 등 주거공용면적) 기준입니다. 전용면적을 그대로 평으로 환산해 평당가를 매기면 실제 시세 기사·부동산 사이트에서 보는 값보다 25~35% 높게 나옵니다.

이 API에는 공급면적 자체가 없고, 단지·주택형별 공급면적은 별도의 공공데이터포털 데이터셋으로도 안정적으로 조회할 수 없어서(분양 공고 PDF나 부동산 정보 사이트에 개별적으로만 존재), 검단신도시 여러 단지(검단신도시푸르지오더베뉴, 유승한내들에듀파크, 검단신도시예미지트리플에듀 등)의 실제 분양·관리비 고지 면적을 찾아 확인한 **전용률**(전용면적 ÷ 공급면적)을 바탕으로 공급면적을 역산합니다. 확인해보니 전용률이 전용면적 구간별로 74~79% 안팎에 모여 있어(예: 전용 75.84㎡→공급 99.07㎡, 전용 84.24㎡→공급 109.43㎡, 전용 102.85㎡→공급 130.65㎡), 아래처럼 구간별 평균값을 `scripts/kakao-realestate-news.js`의 `EXCLUSIVE_RATIO_BANDS`에 넣어뒀습니다.

| 전용면적 | 적용 전용률 |
| --- | --- |
| 60㎡ 미만 | 75.0% |
| 60~80㎡ 미만 | 76.5% |
| 80~95㎡ 미만 | 76.8% |
| 95~120㎡ 미만 | 78.5% |
| 120㎡ 이상 | 80.0% |

이렇게 역산한 공급면적은 단지마다 등기부에 등록된 정확한 값과는 소수점 단위로 다를 수 있는 **추정치**입니다. 페이지 하단의 "평당가는 공급면적 추정치 기준" 안내가 이 뜻입니다. 더 정확한 값이 필요하면 새로 조회된 단지의 실제 공급면적을 찾아 `EXCLUSIVE_RATIO_BANDS`를 단지별 값으로 세분화하세요.

### 참고

- 실거래 신고는 계약 후 최대 30일까지 지연될 수 있어 이번 달 초에는 자료가 거의 없을 수 있습니다. 그래서 이번 달부터 `GEOMDAN_TRANSACTION_MONTHS`개월 전 달까지(기본 4개월이면 다섯 달치, 조회 기간의 첫날이 걸친 달까지 보려고 기간보다 한 달 더 봅니다) 달마다 조회한 뒤, 기간 안의 건 중 평당가가 높은 순으로 보여줍니다.
- **실거래가 조회 예산과 임시 데이터**: data.go.kr 조회에는 `GEOMDAN_TRANSACTION_FALLBACK_BUDGET_MS`(기본 30초) 예산만 줍니다. 이 시간 안에 끝나지 않으면(API 키 문제로 즉시 실패하는 경우든, 응답이 느려 시간을 넘기는 경우든) 그 자리에서 조회를 포기하고, 가장 최근에 성공했던 조회 결과를 `docs/geomdan-transactions-cache.json`에서 불러와 "임시 데이터"라는 안내 문구와 함께 대신 보여줍니다(실거래가 목록 위 노란 안내 박스). 이건 그 실행 한정 응급 처치이고, 다음 실행이 API에 정상적으로 접근되면 그때 새로 받아온 데이터로 캐시와 페이지가 자동으로 교체됩니다. 대체할 캐시조차 없으면(예: 캐시 파일을 처음 만들기 전) 예전처럼 실거래가 섹션만 빈 채로 나머지는 정상 진행됩니다. 키 자체가 문제라면 재시도로 해결되지 않으니 7-1의 키 발급 상태를 먼저 확인하세요. `docs/geomdan-transactions-cache.json`은 다른 두 페이지처럼 워크플로가 매번 커밋하므로 직접 수정하지 마세요.
- **`LAWD_CD=28290`(검단구)인 이유**: 2026년 7월 1일 인천시 행정구역 개편(법률 제20161호)으로 검단신도시 일대가 기존 서구에서 분리되어 별도 자치구 "검단구"가 됐습니다. 예전 서구 코드(`28260`)는 더 이상 이 지역 실거래를 포함하지 않습니다. 나중에 이 지역이 또 개편되어 실거래가가 갑자기 0건으로 보인다면, 가장 먼저 지역코드가 바뀌지 않았는지 의심해보세요.

## 8. 수동으로 카카오톡 알림 보내기 (선택)

평소 뉴스/실거래가 자동 발송과 별개로, 저장소 관리자가 임의의 문구를 즉시 카카오톡으로 보내고 싶을 때(예: 설정 변경 점검 결과 알림) 쓰는 기능입니다.

저장소 **Actions → Morning Real Estate News to KakaoTalk → Run workflow**에서 `notify_message` 입력란에 보내고 싶은 문구를 채우고 실행하면, 그 실행에서는 평소의 뉴스 수집·`docs/index.html`·`docs/geomdan.html` 갱신을 전부 건너뛰고 입력한 문구만 카카오톡으로 즉시 전송합니다. 입력란을 비워두고 실행하면 평소와 동일하게 동작합니다.

## 9. skip_kakao_send로 자동 발송만 건너뛰기 (선택)

10번 문단에서 설명하는 큐레이션 브리핑을 만들 때, 그 재료가 되는 오늘자 뉴스·실거래가 데이터를 새로 받아와야 합니다. 그런데 평소처럼 워크플로를 실행하면 `docs/index.html`·`docs/geomdan.html` 갱신과 함께 카카오톡 자동 다이제스트도 같이 나가버려서, 잠시 뒤 큐레이션 브리핑까지 보내면 같은 날 비슷한 내용의 카카오톡 메시지가 두 번 겹치게 됩니다.

`skip_kakao_send` 입력을 `true`로 두고 워크플로를 실행하면 뉴스·실거래가 수집과 `docs/index.html`·`docs/geomdan.html`·실거래가 캐시 갱신은 평소대로 하되, 카카오톡 자동 다이제스트 발송만 건너뜁니다. 큐레이션 브리핑을 새로 만들기 직전에 이 옵션으로 한 번 실행해서 재료 데이터만 최신으로 만들어두는 용도입니다.

10번 문단의 큐레이션 브리핑이 하루 두 번(오전 7시·오후 7시) 자동으로 도는 지금은, 정기 스케줄(`schedule`)로 실행되는 경우 `workflow_dispatch` 입력 없이도 항상 이 옵션이 자동으로 켜진 것처럼 동작합니다(카카오톡 자동 다이제스트는 항상 건너뛰고 페이지 갱신만 함). 수동으로 **Run workflow**를 눌러 실행할 때는 예전처럼 `skip_kakao_send` 입력값을 그대로 따릅니다(비워두면 평소대로 카카오톡도 발송).

## 10. 사람이 직접 고르는 큐레이션 카드뉴스 — 재부키 부동산 분석 (docs/briefing-infographic.html)

`docs/index.html`·`docs/geomdan.html`(자동 다이제스트)은 `when:1d` 필터를 통과한 뉴스 후보를 전부 그대로 나열합니다. 개수는 많지만 판단 없이 나열만 하는 방식이라, 관련 없는 기사(예: "거래량" 키워드로 걸린 암호화폐 시세 기사)나 홍보성 기사가 섞여 들어올 수 있고, 어떤 기사가 실제로 부동산 흐름을 이해하는 데 도움이 되는지는 걸러주지 않습니다.

`docs/briefing-infographic.html`("재부키 부동산 분석" 카드뉴스)은 그 후보 중에서 사람(또는 이 저장소를 관리하는 Claude 세션)이 직접 제목과 본문을 읽고, 부동산 흐름을 이해하는 데 실질적으로 도움이 되는 이슈만 골라 4장짜리 인스타그램 카드뉴스 형식(표지 → 좌우분할 이슈 4건 → 오버레이 경고·트렌드 → 실거래 랭킹) + 맨 아래 전체 기사·실거래가 목록으로 정리한 버전입니다. (좌우분할 이슈는 처음엔 2건이었다가, "이슈가 2개뿐이니 4개로 늘려달라"는 요청으로 4건으로 늘었습니다 — 절대 2건으로 되돌리지 마세요.) 자동으로 재생성되지 않고, 아래 절차를 실행할 때만 그 시점의 스냅샷으로 갱신됩니다. (예전에는 검단 아라역 롯데캐슬 넥스티엘 공식 조감도를 보여주는 고정 슬라이드가 하나 더 있었는데, 오늘 뉴스가 아닌데 오늘자처럼 보인다는 지적으로 제거했습니다.)

> 2026년 9월 10일부터 카카오톡 자동 발송 대상을 텍스트 브리핑 `docs/briefing.html`에서 이 카드뉴스로 완전히 교체했습니다. `docs/briefing.html`·`docs/briefing.pdf`는 더 이상 자동 갱신·발송되지 않고, 마지막으로 갱신된 상태로 저장소에 남아 있습니다(필요하면 수동으로 계속 쓸 수 있습니다).

### 슬라이드 구성

| 슬라이드 | 역할 | 갱신 방식 |
| --- | --- | --- |
| 1. 표지 | 오늘의 헤드라인 이슈 1건(표지 사진은 링크 미리보기 사진 `og:image`로도 쓰임 — `build-card.js`가 <head>에 자동으로 맞춤) | 매 실행마다 새로 판단·작성, 사진도 실제 기사에서 추출 |
| 2. 핵심 이슈 | 핵심 이슈 4건 | 매 실행마다 새로 판단·작성, 사진도 실제 기사에서 추출. 인스타그램 카드뉴스 스타일로 이슈마다 사진(원본 비율, 폭 100%) → 검은 '이슈 N' 태그 → 제목(둘째 줄 노란 형광펜) → 본문 순으로 세로로 쌓는다 |
| 3. 오버레이 | 시장 경고·트렌드 1건 | 매 실행마다 새로 판단·작성, 사진도 실제 기사에서 추출 |
| 4. 실거래 랭킹 | 검단신도시 실거래가 전체 순위(단지별 최고 평당가 기준, 중복 단지 제거, 상한 없이 전부 표시, 각 줄에 해당 거래의 실거래가와 평당가를 함께 표시) | 매 실행마다 최신 데이터로 갱신 |

슬라이드 4(실거래 랭킹)는 같은 단지의 여러 거래 중 평당가가 가장 높은 1건만 남기고(예: 힐스테이트신검단센트럴이 여러 건 있어도 최고가 1건만), 그렇게 단지별로 추린 값을 평당가 높은 순으로 정렬해 **고유 단지 전체**를 보여줍니다(순위는 하단 목록의 건수 상한과 무관하게 조회 기간 안 전체 거래로 만듭니다 — 7-3의 "목록 상한과 단지 순위" 참고). 처음엔 상위 4건→20개→30개로 순서대로 늘렸는데, 30개로 자르면 어떤 날은 30위 밑으로 잘리는 단지가 생긴다는 지적에 따라 아예 상한을 없앴습니다 — **절대 다시 고정 상한(20개·30개 등)을 두지 마세요.** `bold-sub`의 "MARKET RANKING TOP N" 라벨은 그날 실제로 나온 고유 단지 수를 그대로 씁니다(예: 27곳이 나오면 "TOP 27"). 예전에는 이 중복 제거 없이 전체 거래 중 상위 4건만 그대로 보여줬는데, 그러면 한 단지가 여러 층·타입으로 거래되며 TOP4를 독식하는 경우가 많아(예: 같은 단지가 4자리 중 3자리 차지) 실제로는 다양한 단지 시세를 보여주지 못한다는 지적이 있었습니다.

슬라이드 1·2·3의 사진은 `scripts/resolve-article-images.js`로 그날 고른 기사에서 실제로 가져옵니다. 구글 뉴스 RSS 링크는 자바스크립트 SPA로만 실제 기사로 연결돼 일반 `fetch`로는 대표 이미지를 가져올 수 없다는 걸 처음엔 실제 테스트로 확인했지만(모든 기사가 동일한 구글 아이콘만 반환됨), 실제 브라우저(Playwright)로 그 리다이렉트를 실행시키는 방식으로 해결했습니다. `morning-realestate-kakao.yml`의 `resolve_image_urls` 입력에 구글 뉴스 링크를 줄바꿈으로 넣으면, 각 링크의 최종 언론사 URL과 대표 이미지(og:image)를 로그에 출력합니다 — 언론사 CDN의 Referer 검사로 인한 핫링크 차단 여부(`hotlinkOk`)도 함께 확인하므로, `hotlinkOk: false`가 나오면 그 이미지는 쓰지 않고 다른 후보를 고릅니다. 이 단계는 `resolve_image_urls`를 채웠을 때만 Playwright+Chromium을 설치해 실행되므로, 평소 하루 2번 다이제스트 갱신(이 입력 없이 실행)에는 전혀 영향이 없습니다.

### 갱신 절차

1. **재료 데이터 새로 받기**: `morning-realestate-kakao.yml`을 `skip_kakao_send: true`로 실행합니다. 완료될 때까지 기다립니다(보통 1분 이내, 실거래가 API가 느리면 최대 예산 30초+α 더 걸릴 수 있음).
2. **후보 읽기**: 갱신된 `docs/index.html`을 읽어 일반 부동산 뉴스 후보(보통 최대 20건)와 검단신도시 뉴스 후보(있으면 최대 20건, 없는 날도 있음)를 확인합니다.
3. **판단·선별**: 표지(슬라이드1)용 헤드라인 이슈 1건, 좌우분할(슬라이드2)용 핵심 이슈 4건, 오버레이(슬라이드3)용 시장 경고·트렌드 1건을 고릅니다. 광고성·얕은 재탕 기사는 제외하고, 검단신도시 직접 언급 기사가 있으면 우선 반영합니다(부동산 시장 얘기가 아니어도 검단 관련이면 후보로 고려 — `GEOMDAN_QUERY`가 검단 언급 기사는 분야 상관없이 다 잡도록 넓혀져 있습니다). 검단신도시 뉴스가 없는 날은 억지로 채우지 말고 기존에 검단 관련 이슈가 없었다는 사실 자체를 반영해 다른 후보로 채웁니다. "인접지역" 딱지가 붙은 기사(예: 7호선 청라 연장)를 쓸 때는 그 지역이 아직 검단까지 연결되지 않았다는 사실을 왜곡하지 않도록 주의합니다.
4. **이미지 추출**: 고른 6건(표지 1 + 좌우분할 4 + 오버레이 1)의 구글 뉴스 링크를 `morning-realestate-kakao.yml`의 `resolve_image_urls` 입력(줄바꿈 구분)에 담아 실행합니다. 이때 `skip_kakao_send: true`도 반드시 같이 넣습니다 — 둘 중 하나만 빼먹으면 옛날 방식 자동 텍스트 다이제스트가 그대로 발송돼버립니다(실제로 이 실수로 잘못된 메시지가 나간 적이 있습니다). 실행 로그에서 `RESOLVED {...}` 줄을 읽어 각 기사의 `image`와 `hotlinkOk`를 확인합니다. `hotlinkOk`가 `true`여도 이미지가 사이트 공용 로고·아이콘(예: `images/common/사이트명.png` 같은 경로)이면 실제 기사 사진이 아니므로 다른 후보로 교체합니다. `hotlinkOk`가 `false`이거나 이미지가 없어도 마찬가지로 다른 후보로 교체하거나(선호), 부득이하면 사진 없이 텍스트만으로 구성합니다.
5. **요약 작성**: 고른 이슈마다 원문을 그대로 옮기지 말고, 카드뉴스 톤(짧고 임팩트 있는 헤드라인 + 1~2문장 요약)으로 직접 써서 슬라이드 1·2·3 텍스트를 교체합니다.
6. **실거래가 반영**: 슬라이드 4의 실거래 랭킹과 전체 목록 섹션(일반 뉴스 전체 + 검단 뉴스 전체 + 실거래가 최대 800건)을 오늘자 데이터로 갱신합니다. 랭킹은 `docs/index.html`에 함께 실린 단지별 최고 거래 데이터(없으면 하단 실거래가 목록)를 단지명 기준으로 묶어 단지별 최고 평당가 1건만 남긴 뒤(같은 단지가 여러 번 나오지 않게), 평당가 높은 순으로 정렬해 **상한 없이 고유 단지 전체**를 뽑습니다. `bold-sub` 라벨("MARKET RANKING TOP N")의 N은 그날 실제로 나온 고유 단지 수로 씁니다. 전체 목록 섹션은 `docs/index.html`이 이미 만들어둔 `<li class="article">`/`<li class="txn">` 마크업을 그대로 재사용하면 됩니다(직접 다시 계산하지 않기).
7. **페이지 조립**: `docs/briefing-infographic.html`을 열어 슬라이드 1·2·3·4와 전체 목록 섹션만 교체합니다. 슬라이드 1·2·3은 4단계에서 얻은 실제 이미지 URL을 그대로 씁니다. CSS·디자인 토큰(브랜드 컬러·폰트 등)은 건드리지 않습니다 — 단, 슬라이드 1(표지)·3(오버레이)과 슬라이드 2(좌우분할)의 사진은 예외로, 사진을 억지로 박스에 채우거나(`cover`) 줄여 넣지(`contain`) 않고, 사진 원본 비율 그대로 폭 100%·높이 auto로 보여주면서 슬라이드(카드) 자체가 사진 높이에 맞춰 늘어나도록 만들어뒀습니다(`.cover-photo`/`.overlay-photo`를 실제 `<img>`로 두고 `.cover-content`/`.overlay-content` 텍스트를 같은 그리드 칸에 겹쳐 오버레이하는 구조). 사진이 세로로 길면 카드도 그만큼 길어지는 게 의도된 동작이니 그대로 두고, 다시 고정 높이 박스나 `object-fit`/`background-size: cover`·`contain`으로 되돌리지 마세요.
8. **검증**: Playwright로 데스크톱(~700px)·모바일(~390px) 두 뷰포트에서 가로 스크롤 없음, 텍스트 겹침 없음을 확인합니다. 이미지 자체는 샌드박스 네트워크 제약으로 로컬에서 안 뜰 수 있으니(정상), 4단계의 `hotlinkOk` 확인으로 대신합니다.
9. **커밋·배포**: 이 저장소의 일반적인 브랜치 규칙에 따라(`claude/morning-realestate-news-kakao-q55sf2` 브랜치, PR 생성 후 머지) `docs/briefing-infographic.html`을 커밋·푸시·PR·머지합니다. GitHub Pages 배포(`pages build and deployment` 워크플로)가 끝날 때까지 기다립니다.
10. **카카오톡 발송**: `morning-realestate-kakao.yml`을 `notify_message`는 비워두고 `skip_kakao_send: true`와 `send_briefing_images: true`를 함께 켜서 실행합니다. 이렇게 하면 카드뉴스를 캡처한 사진 한 장에 링크가 함께 담긴 메시지 한 통만 나갑니다 — 링크만 따로 문자 메시지로 보내지 않습니다(`notify_message`를 채우면 그 문구가 담긴 별도 문자 메시지가 먼저 나가버리므로 반드시 비워두세요).

### 11. 카드뉴스를 이미지 파일로도 카카오톡에 전송하기

`send_briefing_images: true`를 켜면, 위 9단계에서 이미 배포한 `docs/briefing-infographic.html`을 Playwright로 다시 열어 표지부터 검단신도시 실거래 평당가 TOP10까지를 자르지 않고 이어붙인 세로로 긴 이미지 한 장으로 캡처해서 카카오톡 이미지 메시지 한 통(사진+링크)으로 전송합니다. 사진 여러 장으로 쪼개거나 가로세로 비율을 맞추려 자르지 않고, 카드뉴스 자체가 늘어난 그대로 세로로 긴 사진 한 장을 보냅니다(사진 여러 장 대신 하나만 보내달라는 요청, 그리고 카드뉴스 사진이 잘리거나 줄어들지 않게 해달라는 요청에 따른 동작입니다). 실거래 랭킹은 페이지 전체(고유 단지 전부)가 아니라 TOP10까지만 잘라내며, 원래 있던 "MARKET RANKING TOP N"·"전체를 다 보여드립니다" 문구는 캡처 순간에만 "TOP 10"·"전체 N곳 중 상위 10곳" 문구로 바꿔서 개수가 안 맞는 오해를 막습니다(실제 배포 파일은 그대로 둡니다).

- **관련 스크립트**: [`scripts/capture-briefing-images.js`](../scripts/capture-briefing-images.js)(캡처), [`scripts/send-kakao-images.js`](../scripts/send-kakao-images.js)(전송).
- **동작 순서**: 캡처(사진 한 장) → `docs/kakao-captures/`에 커밋·푸시(다른 커밋처럼 자동으로) → GitHub Pages 배포를 짧게 기다림(이미지 URL이 200으로 응답할 때까지 최대 약 2분 재시도) → 카카오톡으로 전송(사진+링크가 함께 담긴 메시지 한 통).
- **반드시 `docs/briefing-infographic.html` 배포 이후에 켜세요**: 이 옵션은 그 시점에 GitHub Pages에 떠 있는 페이지를 그대로 찍습니다. 배포 전에 켜면 어제 내용이 찍힙니다.
- **토큰 재사용**: 이미지 전송은 같은 실행 안에서 `kakao-realestate-news.js`가 이미 발급받은 `access_token`을 그대로 씁니다(각자 새로 토큰을 받으면 그 사이 카카오가 `refresh_token`을 회전시켰을 때 나중 호출이 이미 무효화된 옛 토큰을 쓰게 될 위험이 있어 이를 피했습니다).
- **이미지 규격**: JPEG·폭 618px 안팎으로 품질 82로 압축합니다. 카드뉴스 사진들이 원본 비율 그대로 세로로 이어지므로 예전(조각당 몇백 KB 수준)보다 파일 용량이 커질 수 있습니다 — 실제 전송 로그의 `CAPTURED ... KB` 줄로 매번 크기를 확인하고, 카카오톡에서 사진이 안 보이는 등 문제가 생기면 `CAPTURE_JPEG_QUALITY` 환경 변수를 낮추는 것을 고려하세요.

### 12. 조립·검증 스크립트 (`scripts/card-news/`)

갱신 절차의 5~8단계는 스크립트로 자동화돼 있습니다. HTML을 손으로 고치거나 `docs/index.html`·실행 로그를 통째로 읽지 말고 아래 도구를 쓰세요(토큰·실수 절약).

**(토큰 절약) 묶음 도구 `run.js`**: 루틴은 아래 1~5단계를 `node scripts/card-news/run.js prepare <폴더>` → `images <폴더> <번호 6개>` → `finalize <폴더> --title <제목>` 세 번으로 돌립니다(`prepare`는 수집·후보 `--compact`·직전 카드·인사이트 자료 목록, `images`는 링크 파일·이미지 추출·본문 발췌 600자, `finalize`는 조립·검증·커밋·PR·Pages·브랜치 재동기화). 인사이트에 쓸 검증된 제도·수치는 `docs/insight-facts.md`에 모아 두고 30일 안이면 WebSearch 없이 씁니다. 아래는 각 단계가 안에서 하는 일입니다.

1. **후보 보기** — `node scripts/card-news/candidates.js [--index <index.html>]`: 일반 뉴스·검단 뉴스 후보를 번호와 제목으로만 출력합니다. `--prev`는 직전 카드의 표지·이슈·오버레이 제목을 보여줍니다(같은 기사·후속 기사 반복 방지용). 고른 번호를 인자로 주면(`candidates.js 3 7 21`) 그 기사들의 구글 뉴스 링크가 줄바꿈으로 출력되며, 그대로 `resolve_image_urls` 입력에 넣으면 됩니다(입력 순서가 결과의 `n`).
2. **이미지 확인** — `node scripts/card-news/actions.js resolved <run_id>`가 잡 주석에 남은 추출 결과를 한 줄씩 출력합니다(`{"n":입력 순서,"hotlinkOk":...,"host":...,"image":...}`, 로그를 읽을 필요 없음). `hotlinkOk`가 `true`여야 하고, `image`는 `https`여야 하며(`http`면 같은 주소를 `https`로 바꿔 다시 확인), 150px 안팎의 작은 썸네일(`..._v150.jpg` 등)이나 사이트 공용 로고는 다른 후보로 바꿉니다.
3. **조립** — 슬라이드 1~3 내용을 아래 형식의 JSON(임시 파일, 커밋하지 않음)으로 쓰고 `node scripts/card-news/build-card.js --content <content.json> --index <index.html> --links <links.txt>`을 실행하면 슬라이드 1~3, 슬라이드 4 랭킹(고유 단지 전체, 각 줄에 실거래가와 평당가, 요약 문구는 데이터로 자동 생성), 하단 전체 목록(뉴스+검단 뉴스+실거래가)이 한 번에 갱신됩니다. `--txn-only`는 하단 목록 중 실거래가 구간만 교체합니다.
4. **검증** — `node scripts/card-news/validate-card.js [--out <폴더>]`: 데스크톱(700px)·모바일(390px)에서 가로 스크롤·겹침·잘림·카드 이음매·랭킹 우측 열 충돌을 검사하고(문제가 있으면 종료 코드 1) 스크린샷을 저장합니다. 이미지는 샌드박스에서 안 뜨므로 회색 자리표시자로 대체합니다.

5. **워크플로·PR 보조** — `gh api`만 쓰는 `node scripts/card-news/actions.js`로 MCP 도구 없이도 처리합니다(Bash timeout은 600000 권장).
   - `dispatch <작업 브랜치> skip_kakao_send=true`: 데이터 갱신 실행 후 끝날 때까지 대기. 이미지 추출은 `dispatch <작업 브랜치> skip_kakao_send=true --links <링크 파일>`(링크 파일은 `candidates.js <번호들>` 출력을 저장한 것)로 실행하고, 끝나면 `resolved <run_id>`로 결과를 읽습니다.
   - 발송: `dispatch main skip_kakao_send=true send_briefing_images=true` 후 `steps <run_id>`로 "Send briefing card images to KakaoTalk"가 success인지 확인합니다.
   - `pr-merge --head <브랜치> --title <제목> --body-file <파일> [--commit-file <파일>]`: PR(draft) 생성 → ready → squash 머지. 이어서 `pages <머지 sha>`로 Pages 배포 완료를 기다립니다.
   - `resolve_image_urls`에 `skip_kakao_send=true`가 빠졌거나, 발송 단계에 `notify_message`·`resolve_image_urls`를 넣거나, 발송을 main이 아닌 ref에서 실행하려 하면 실행 전에 거부합니다.

`content.json` 형식(텍스트는 한국어로만, 이미지 주소는 반드시 3단계에서 확인한 https 주소):

```json
{
  "cover":   { "img": "https://...", "alt": "...", "headline": ["1줄", "강조할 2줄", "3줄"], "highlight": 1,
               "summary": "1~2문장", "tags": ["# 태그1", "# 태그2", "# 태그3"] },
  "issues":  [ { "img": "https://...", "alt": "...", "title": "제목(줄바꿈은 \n)", "text": "1~2문장" } ],
  "outlets": "문화일보 / 연합뉴스 / 뉴뉴스 / 헤럴드경제",
  "overlay": { "img": "https://...", "alt": "...", "script": "검은 태그에 들어갈 짧은 문구", "lead": ["1줄", "2줄"],
               "body": "1~2문장", "insight": "재부키 인사이트 본문", "source": "KBS 뉴스" },
  "sources": { "cover": "서울경제", "split": "문화일보 + 연합뉴스 + ...", "overlay": "KBS" }
}
```

- `issues`는 1~4건입니다(2026-11-16 개편: 검단에 영향을 주는 전국 이슈만 넣고 억지로 채우지 않습니다). 슬라이드 4는 랭킹 TOP 5만 보이고 나머지 단지·차트·전체 뉴스 목록은 접혀 있습니다. `cover.category`를 생략하면 한국시간 기준 날짜·요일·아침/저녁이 자동으로 들어갑니다. 랭킹 요약 문구를 직접 쓰고 싶을 때만 `rankPill`을 추가합니다.
- 슬라이드 4 제목은 "검단신도시 실거래 평당 순위"이고, 랭킹 각 줄 오른쪽에는 평당가가 위에, 그 거래의 실거래가가 그 아래에 함께 표시되고, 1위 단지 이름 옆에는 왕관 아이콘(인라인 SVG)이 붙습니다(`build-card.js`가 만드는 마크업 그대로 유지).

### 지켜야 할 것

- 응답·페이지 문구는 반드시 한국어로만 씁니다(일본어 등 다른 언어를 섞지 않습니다).
- 없는 내용을 억지로 채우지 않습니다.
- 기사 페이지를 직접 열어 광고량을 확인할 수는 없으므로, 매체 성격과 문구 톤으로 판단합니다.
- 매 실행마다 어떤 이슈를 고를지는 그날의 실제 후보와 판단에 따라 달라집니다 — 자동 다이제스트처럼 완전히 같은 규칙으로 똑같이 재현되지는 않습니다.

### 자동 실행 일정

매일 한국시간 오전 7시·오후 7시, 위 절차 전체(재료 데이터 갱신 → 판단·선별 → 페이지 조립 → 검증 → 커밋·배포 → 카카오톡 발송)를 수행하도록 예약돼 있습니다(Claude Code Remote의 Routine 기능, GitHub Actions의 `schedule` 트리거가 아니라 별도 스케줄러라 정시에 더 안정적으로 실행됩니다). 시간을 바꾸거나 끄고 싶으면 Routine 목록에서 이 카드뉴스용 항목을 찾아 수정·삭제하면 됩니다.

## 발송 안정화 (2026-10-11)

- 캡처 이미지 파일명에 KST 시각이 들어간다(`briefing-full-YYYYMMDD-HHMM.jpg`). 같은 이름을 덮어쓰지 않아 CDN·카카오 미리보기 캐시가 옛 이미지를 보여주는 일을 막는다.
- 캡처 전에 배포된 카드(`briefing-infographic.html`)가, 캡처 후에는 이미지가 체크아웃한 파일과 SHA-256까지 같을 때만 다음 단계로 간다. 시간 안에 일치하지 않으면 발송 없이 실패한다(옛 내용·깨진 이미지 발송 방지).
- Playwright 설치는 시도마다 4분 제한, 최대 3회 재시도(스텝 전체 15분 제한)라 멈춰도 알아서 끝난다.
- `resolve_image_urls`는 이미지 주소를 자동 보정한다: `//`·`http`→`https`, `/news/thumbnail/..._v150`→`/news/photo/...`, `.cache/512/` 제거. 결과의 `note`에 보정/로고/작은 썸네일/작은 용량 경고가 나오고 `actions.js resolved`가 함께 출력한다. 로고·작은 썸네일 경고가 나오면 다른 후보로 교체한다.

## 단지별 사이클 페이지 (docs/geomdan-cycle.html)

| 지표 | 계산 |
| --- | --- |

### 카드 랭킹에 바로 표시

별도 링크는 두지 않는다. `build-card.js`가 같은 기록(`docs/geomdan-history-cache.json`)으로 위 지표를 계산해 카드 슬라이드 4(검단신도시 실거래가 랭킹)의 각 단지 줄 아래에 칩(추세 · 고점 대비 · 국면 · 강도)으로 붙이고, 단지를 눌러 펼치면 맨 위에 3년 평당가 추세 차트(3개월선·12개월선·고점·신고가 ▲·거래량)와 지표 풀이가 나온다. 기록 8건 미만이거나 최근 3개월에 3개월선이 없는 단지는 칩 없이 표시된다. `docs/geomdan-cycle.html`은 기록 갱신용으로 계속 만들어지지만 카드·index.html에서 링크하지 않는다.

랭킹 맨 아래(요약 문구·칩 읽는 법 다음)에는 "검단신도시 전체 흐름"(3개월 중위 평당가·추세·고점 대비·최근 3개월 신고가 + 3년 평당가 추세 차트)과 "거래량·가격 4분면"(단지별 점 + 국면별 단지 수)이 붙는다. 카카오톡 캡처 이미지는 TOP10까지만 담으므로 이 부분은 링크로 들어가 본다. 제외 목록(`scripts/geomdan-excluded-apartments.txt`)에 새로 넣은 단지는 다음 데이터 갱신 전이라도 `build-card.js`가 랭킹·지표에서 바로 뺀다.

### 검단신도시 부동산 기사는 우선순위(억지로 넣지는 않는다)

2026-10-27 정정: 검단신도시 부동산 기사(분양·청약·입주·실거래·교통·개발·정비 등)는 카드 선정에서 우선순위로 올리되, 쓸 만한 기사가 없으면 억지로 넣지 않는다. `candidates.js`는 후보 목록 맨 아래에 `[검단 부동산 우선 후보 번호]`를 보여 주고, 목록 앞에는 같은 사건을 다룬 매체 수(`[매체 N]`, 많을수록 핫한 뉴스)와 발행일(`[MM.DD]`)을 붙인다. 하루 두 번(오전 7시·오후 7시) 그 시점에 가장 핫한(매체 수 많고 방금 나온) 뉴스를 고른다. 검단 뉴스 목록에는 부동산 기사(제목에 분양·청약·입주·아파트·전세·재개발·개통·철도 등)와 구 전체 주요 사건(대형 사고, 분구 정산금 갈등·재정 위기 등)만 남기고, 기부·복지관 수업·행사 같은 지역 동정은 뺀다(`scripts/geomdan-common.js`의 `isGeomdanNews`). 카드뉴스의 검단 우선 후보는 부동산 기사만(`isRealEstateNews`). 단, 검단 AA17블록(중흥S클래스) 관련 기사는 검단에서 가장 관심이 큰 소식이라 "무조건" 카드에 넣는다(2026-10-31 사용자 요청): candidates.js 맨 아래 "[검단 AA17 필수 번호]"에 번호가 있으면 반드시 표지나 이슈 중 한 칸에 쓴다(이미 카드에 쓴 같은 기사는 [최근사용]으로 빠지니 새 기사만 해당). 국토부 등 정부의 국가 교통 인프라 계획(국가철도망 구축계획·광역교통 기본/시행계획·광역교통개선대책·국가도로망 등) 기사도 "무조건" 카드에 넣는다(2026-11-08 사용자 요청): candidates.js 맨 아래 "[국가 교통정책 필수 번호]"에 번호가 있으면 반드시 표지나 이슈 중 한 칸에 쓴다(이 기사들은 제목에 "부동산"이 없어도 별도 검색으로 부동산 뉴스 끝에 덧붙고 [A정책]으로 표시된다. 7호선 연장·GTX 개별 노선 소식은 해당하지 않으며, 원문에 없는 노선을 계획에 포함됐다고 쓰지 말 것). 같은 사건은 한 건만 보인다: 글자 겹침이 낮아도 사건 종류(폭발·화재·정산 갈등)나 큰 금액(예: 648억)이 같으면 하나로 묶고, 가장 자세한 제목을 대표로 남긴다(`geomdanEventKeys`). 목록 항목에는 `data-pub`(발행일)와 `data-src`(매체 수)가 남는다.

### 새로 신고된 거래 · 이번 주 일정 블록 (2026-11-16)
- 슬라이드 4 상단에 `build-card.js`가 자동으로 넣는다. 거래는 `docs/geomdan-transactions-cache.json`의 `firstSeen`(우리가 처음 본 날, 국토부 자료에 신고일이 없어 근사)이 최근 3일인 건을 보여 주고, 아직 없으면 계약일이 가장 최근인 건을 "최근 계약 거래"로 보여 준다. 직전 같은 단지·평형 거래와 비교하고, 자료에서 사라진 거래(`removed`, 14일 보관)는 "거래 해제 또는 정정"으로 표시한다.
- 검단 실거래는 하루 한 번만 새로 받는다(오늘 이미 받았으면 캐시 재사용, `GEOMDAN_FORCE_REFRESH=true`로 강제). 뉴스는 기존대로 하루 두 번.
- "이번 주 일정"은 `docs/schedule.json`(`date`, `title`, `note`, `source`)에서 오늘~7일 뒤 항목만 보여 주고 지난 날짜는 저절로 빠진다. 청약·입주·개통 일정은 기사로 확인한 것만 출처와 함께 추가한다.

## 지역 선택형 아침 브리핑 (docs/regions/)

검단 말고 전국 어느 동네 사람도 볼 수 있게, 시·도 → 시군구를 고르면 그 동네 부동산 소식·최근 실거래가·전국 부동산 뉴스를 한 화면에 보여준다. 주소는 `https://lifelongdt-beep.github.io/game/regions/`이고, `#r=28185`(시군구 코드)나 `#r=mine`(나만의 동네)을 붙이면 바로 열린다. 고른 동네, 뉴스 주제, 나만의 동네 설정은 기기에 기억되고, 휴대폰 홈 화면에 추가하면 앱처럼 열리며, 인터넷이 끊겨도 마지막으로 본 화면이 보인다.

- **화면**: `docs/regions/index.html` 한 장이 `docs/regions/data/`의 JSON을 읽어 동네 고르기·뉴스 주제 고르기·법정동 좁히기를 브라우저에서 처리한다.
- **수집**: `scripts/regional-briefing.js`를 별도 워크플로 `regional-briefing.yml`이 매일 04:37 KST에 한 번 돌린다(전국을 모으느라 수십 분 걸려 아침 뉴스 워크플로와 분리). 수동 실행 때 `region_codes`에 코드를 넣으면 그 시군구만 모은다.
- **지역 목록**: `scripts/regions-kr.json`(전국 253개 시군구, 행정안전부 법정동코드 2024-08-01 기준 + 2026 인천 검단구 분리 반영). `verified: false`인 인천 중구·동구·서해구(28260)와 화성시(41590)는 2026 행정구역 개편 뒤 실거래 조회 코드가 바뀌었을 수 있다. 실행 로그에 "실거래가 한 건도 오지 않은 시군구" 경고가 뜨면 그 코드를 고친다.
- **나만의 동네**: 여러 시군구의 법정동을 골라 담고, 그 동에서 최근 거래가 있는 아파트를 체크로 넣고 뺄 수 있다. 실거래가는 담은 동·넣은 아파트만 모아 보여주고, 뉴스는 담은 동이 속한 시군구 소식을 합친다. 설정은 서버가 아니라 그 기기 브라우저에만 저장된다.
- **뉴스 주제**: 청약·분양, 정책·대출·세금, 시세·실거래, 재개발·재건축, 전월세, 교통·개발. 기사 제목에 주제 단어가 있으면 그 주제를 붙이고(여러 개 가능), 전국 뉴스는 주제마다 따로 검색한다. 기준은 스크립트 위쪽 `TOPICS`.
- **동네 뉴스 거르기**: 제목에 시군구 이름(시 아래 구는 시 이름도 인정, 중구·고성군처럼 이름이 겹치는 곳은 시·도 이름도 필요)과 부동산 단어가 있어야 남긴다.
- **실거래 기록**: `scripts/regional-history.js`가 시군구·달별 원자료(매매 36개월·전월세 24개월)를 `.cache/regions-raw/`에 쌓는다. 이 폴더는 저장소에 올리지 않고 워크플로의 Actions 캐시로 보존한다. 최근 3개월은 매번 다시 받고, 지난 달은 비어 있을 때만 받는다. 공공데이터포털 하루 한도(서비스마다 10,000번) 안에 들도록 서비스마다 하루 8,000번(`REGION_CALL_LIMIT`)까지만 부르고, 최근 달을 먼저 받은 뒤 남는 호출로 지난 기록을 채운다. 처음에는 전국 기록이 다 차기까지 2~3일 걸린다. 캐시가 지워지면 같은 방식으로 다시 채운다.
- **브리핑 실거래가**: 쌓인 기록의 최근 3개월(`REGION_TX_MONTHS`) 매매로 단지 TOP 10과 최근 거래를 보여준다. 오늘 최근 달을 새로 받지 못했으면 "지난 자료"로 표시한다.
- **신고가**: 같은 단지·같은 넓이(전용㎡ 소수점 버림, 84.5㎡·84.9㎡는 같은 84㎡)에서 계약일이 앞선 기록 속 거래(최대 36개월)의 최고가를 넘긴 매매를 신고가로 본다(같은 날 거래끼리는 비교하지 않고, 앞선 거래가 없으면 신고가 아님). 시군구 파일의 최근 거래 한 줄 끝에 이전 최고가를 싣고, 화면은 시군구·나만의 동네 실거래가에 신고가 건수와 목록, 첫 화면 나만의 동네 카드에 최근 3개월 신고가 건수, 아파트 상세 그래프에 빨간 점으로 보여준다. 기록이 다 차기 전 처음 며칠은 그 기간 안의 최고가 기준이다.
- **아파트 상세**: 단지 이름을 누르면 시세 그래프(달마다 중앙값 선 + 거래 점), 매매·전세·월세와 넓이(전용㎡) 선택, 과거 거래 목록이 나온다. 자료는 법정동마다 한 파일 `docs/regions/apt/<시군구 코드>/<동 번호>.json`(동 번호는 `regions-kr.json`의 dongs 순서, 목록에 없는 동은 `x`)이고, 내용이 바뀐 파일만 다시 쓴다. 전국 기록이 다 차면 이 폴더가 수백 MB가 될 수 있어, 저장소가 너무 커지면 기간을 줄이거나(`REGION_HIST_TRADE_MONTHS`, `REGION_HIST_RENT_MONTHS`) GitHub Pages를 Actions 배포로 바꾸는 것을 검토한다.
- **매매·전세 갭**: 아파트 상세의 "매매·전세 갭" 메뉴. 매매와 전세가 모두 있는 넓이 하나를 골라, 달마다 그달까지 최근 3개월 매매 중앙값과 전세 보증금 중앙값을 두 선으로 그리고 그 사이(갭)를 칠한다. 지금 갭·전세가율·1년 전 갭과의 차이, 달별 표를 보여 준다. 전월세 기록 기간(24개월)만큼 볼 수 있다.
- **가격 점검**: 넓이·층·가격을 넣으면 같은 넓이 최근 6개월(적으면 1년, 그래도 적으면 전체) 매매로 예상 시세(중앙값)와 보통 범위(25~75%)를 보여 주고, 넣은 가격이 그보다 싼지 비싼지, 최근 거래 중 몇 건보다 높은지, 최고가 대비 몇 %인지 알려 준다. 층은 저층(1~3층)·중층·고층(최고층의 2/3 이상)별 '거래가 ÷ 그 무렵 중앙값' 비율로 보정한다.
- **시장 흐름과 동네 비교**: 이 단지와 같은 법정동 전체를 검단 사이클 분석과 같은 거래량·가격 4분면(최근 3개월 vs 그 전 3개월: 회복·상승, 과열·막바지, 하락, 바닥 다지기)으로 알려 주고(가격은 넓이별 변동률을 가중 평균), 같은 법정동의 비슷한 크기 구간·준공 ±7년 단지들과 최근 평당가 순위를 보여 준다.
- **분양권·입주권**: 아파트 매매 자료에는 분양권 전매가 없어 '분양권전매 실거래가'(`RTMSDataSvcSilvTrade`)를 따로 받아(`REGION_HIST_PRESALE_MONTHS`, 기본 36개월, 0이면 끔) 원자료 `<YYYYMM>-s.json`에 쌓고 아파트 기록 파일의 `s`에 싣는다. 시세 선·신고가·통계에는 넣지 않고 그래프에 주황 마름모, 과거 거래 목록에 "분양권/입주권" 태그로만 보여 준다. 키는 비밀값 `BUNYANGGUAN`(없으면 `DATA_GO_KR_SERVICE_KEY`)을 쓰고 그 키로 이 서비스가 활용 신청돼 있어야 하며, 연달아 3번 실패하면 그 실행에서는 건너뛴다(최근 거래 갱신 실패로 치지 않음).
- **나만의 동네 여러 개**: 기기 저장값 `briefing-mines` = `[{id, name, areas, ex}]`(예전 `briefing-mine`은 첫 번째로 옮김). 첫 화면에 각각 카드로 보이고 설정 화면에서 이름을 바꾸거나 지울 수 있다. 주소는 `#r=mine-m1`.
- **뉴스 핵심 내용**: 매일 실행이 기사를 진짜 브라우저(Playwright, 워크플로에서 설치하며 실패해도 나머지는 진행)로 열어 대표 설명(og:description)과 본문 첫 문단을 읽고, 매체·기자 머리말과 이메일을 떼어 2~3문장(180자 안쪽)으로 줄여 기사마다 `x`로 싣는다(`scripts/news-summary.js`). AI 요약이 아니라 기사 첫머리를 옮긴 것이다. 대표 사진(og:image)은 다른 사이트에서 걸어도 뜨는 https 주소이고 15KB 이상일 때만 `i`로 싣는다. 링크별 결과는 `.cache/regions-raw/news-x.json`에 14일 보관해 기사 하나는 한 번만 읽고, 하루 읽기 시간은 15분(`REGION_SUMMARY_BUDGET_MS`), 전국 뉴스 먼저 읽고 못 읽은 기사는 다음 날 이어 읽는다. 화면은 제목 아래 3줄로 보여 주고 누르면 펼친다.
- **카드뉴스**: 브리핑 맨 위에 옆으로 넘기는 카드. 검단 카드뉴스 후보 고르기의 가치 등급을 같이 쓴다(`scripts/news-tier.js`, `card-news/candidates.js`도 이 파일을 씀): 기사마다 `g` = P(정부·금융당국 부동산 정책), A(가격·거래·공급 지표), X(행사·설명회·광고·정치 공방 등, 카드에서 뺌), -(판단 불가). 동네 기사 최대 4장(동 이름이 제목에 있는 기사 → P → A → 매체 수 많은 순 → 핵심 내용 있는 기사 → 최신순, 발행 3일 지난 기사 제외) → 전국 정책·시장 기사 1장(동네 기사가 없으면 3장) → 실거래 요약 1장(거래 수·신고가·평당가 중앙값·신고가 상위 3건). 고른 뉴스 주제를 따르고, 사진이 있으면 배경으로, 없으면 색 배경을 쓴다. 카드를 누르면 기사 원문이 열린다. 모양은 기존 "재부키 부동산 분석" 카드(build-card.js)를 따른다: 노랑 #ffe600·먹색, 재 아바타 머리줄, 사진 위 검정 표지와 노랑 형광 헤드라인·해시태그, 흰 이슈 카드(이슈 번호 검정 딱지, 밑줄 형광 제목), 노랑 "전국 한 줄 정리" 카드(흰 체크 상자), 실거래 카드(MARKET 머리말, 신고가 거래 목록과 직전 대비). 글꼴은 Gothic A1(구글 폰트, 못 받으면 기본 글꼴).
- **샘플 "검단신도시"**: 매일 실행이 `data/samples.json`을 만든다. 기존 검단 카드뉴스와 같은 검단구(28290) 당하동·마전동·불로동·원당동을 담고, `scripts/geomdan-excluded-apartments.txt`의 "신도시가 아닌 기존 단지"를 동 제목(`# 당하동` 등) 아래 단지명 그대로 뺀 아파트로 넣는다. 화면은 처음 한 번만 이 샘플을 보통 나만의 동네로 넣고(`briefing-sample-geomdan` 표시), 사용자는 이름·동·아파트를 고치거나 지울 수 있다. 지운 샘플은 다시 생기지 않고 첫 화면의 "샘플(검단신도시) 다시 넣기"로만 되살린다. 제외 목록을 고치면 다음 실행부터 새로 넣는 샘플에 반영된다(이미 넣은 샘플은 사용자 설정이라 그대로 둔다).
- **나만의 동네 시세 흐름과 분석**: 담은 동의 아파트 기록(뺀 아파트 제외)으로 달마다 평당가 중앙값(최근 3개월 창)을 굵은 선, 동이 여럿이면 동별 가는 선, 분양권은 주황 마름모로 따로 그린다. 지금 평당가·1년 변동(같은 단지·넓이끼리 비교해 가중 평균)·기록 고점 대비·전세가율, 흐름 신호, 동별 1년 변동, 많이 오른/덜 오른 단지, 분양권 요약을 보여 준다.
- **지도**: 브리핑 화면에 오픈스트리트맵 지도(Leaflet 1.9.4를 `docs/regions/lib/`에 함께 둠, BSD-2 라이선스)로 동 경계를 그리고, 동마다 1년 변동률(같은 단지·넓이끼리)로 하락 파랑 → 보합 흰색 → 상승 빨강(±10%에서 가장 진함)을 칠한다. 시군구 화면은 최근 거래가 있는 동, 나만의 동네는 담은 동. 경계는 Nominatim에 "시·도 시군구 (동)" 이름으로 물어 기기(localStorage `briefing-geo-v1`)에 저장하고, 1초에 한 번 넘게 묻지 않는다. 단지 위치 점은 주소→좌표 API(브이월드 등) 키가 생기면 매일 실행에서 좌표를 붙여 표시할 예정이다.
- **탑층 표시**: 매매 기록의 필지(시군구·법정동 코드·본번·부번)로 건축물대장 표제부(`BldRgstHubService/getBrTitleInfo`, 실패하면 `BldRgstService_v2`)를 조회해 주거용 동마다 지상 층수를 `.cache/regions-raw/bld/<필지>.json`에 쌓는다(필지마다 한 번, 1년 뒤 다시). 거래의 동·층이 그 동 꼭대기 층이면 아파트 상세 과거 거래에 "탑층" 딱지를 단다(거래에 동이 없으면 단지의 동 높이가 모두 같을 때만). 키는 GitHub 비밀값 `BLD_SERVICE_KEY`(없으면 `DATA_GO_KR_SERVICE_KEY`)에 공공데이터포털 '건축HUB 건축물대장정보 서비스' 활용 신청된 키를 넣는다. 하루 호출은 `BLD_CALL_LIMIT`(기본 8000)까지. 실거래 자료에 호수가 없어 테라스·복층 같은 호실 종류는 알 수 없다.
- **단지 정보**: 같은 필지 조회 때 총괄표제부(`getBrRecapTitleInfo`)도 받아 준공(사용승인일)·세대수·동 수·주차 대수·용적률·건폐율을, 동별 표제부로 최고층·지하층·승강기 수를 모은다(총괄표제부가 없으면 동별 합계). 아파트 기록 파일의 단지마다 `b`로 싣고, 아파트 상세 맨 위 "단지 정보" 칸에 보여 준다. 단지 필지는 그 단지 매매에 가장 많이 나온 필지로 정한다.
- **시험 실행**: `REGION_CODES=28185 REGION_OUT_DIR=/tmp/regions node scripts/regional-briefing.js`.
